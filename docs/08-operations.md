# سند ۰۸ — استقرار، عملیات و گام بعدی

> **نسخه:** v0.1 · محیط‌ها از روز اول جدا هستند؛ هیچ تنظیم محیطی در Git قرار نمی‌گیرد.

## ۱. محیط‌ها

| محیط | هدف | داده | دیپلوی |
|---|---|---|---|
| development | لوکال توسعه‌دهنده | داده ساختگی | docker-compose محلی |
| staging | آزمون یکپارچگی/QA | داده شبیه واقعی (ناشناس) | خودکار از main |
| production | کاربر واقعی | واقعی | tag + تأیید دستی |

## ۲. استقرار (نقشه فاز ۰ و ۸)

- هر اپ/سرویس: Dockerfile multi-stage (بیلد داخل کانتینر، ایمیج نهایی باریک و non-root)
- API stateless → مقیاس افقی؛ WS با sticky session یا Redis adapter؛ SFU روی ماشین/نود جدا با پهنای‌باند تضمینی
- Reverse proxy با TLS (Caddy/Nginx) + rate limit لبه
- Secretها: secret manager محیط (هرگز در image/Git)؛ چرخش دوره‌ای JWT secretها
- مهاجرت DB: مرحله پیش‌دیپلوی، فقط-جلو، با قفل مهاجرت

## ۳. پشتیبان‌گیری و بازیابی

- PostgreSQL: بکاپ روزانه full + WAL پیوسته (RPO ≤ ۱۵ دقیقه)؛ رمزنگاری بکاپ؛ نگهداری ۳۰ روز
- Object Storage: versioning + replication (در صورت ابر)؛ lifecycle حذف رسانه‌های orphan
- بازیابی: runbook مستند + تمرین فصلی «بازیابی آزمایش‌شده» (الزام فاز ۸)
- تخریب فاجعه‌بار: کپی بکاپ در منطقه/دستگاه جدا

## ۴. پایش و هشدار

- Health: `/healthz` (زنده) و `/readyz` (وابستگی‌ها) برای LB
- متریک‌ها: تأخیر p95 API، اتصال‌های WS، صف آپلود، خطاها/دقیقه، مصرف SFU
- لاگ ساخت‌یافته (JSON) بدون PII با request-id برای ردیابی
- هشدارها: نرخ خطا، SSL انقضا، disk، backlog صف، ناهنجاری ورود
- Sentry-سازگار برای خطاهای کلاینت (iOS/Android/Electron)

## ۵. کنترل هزینه (حدسی برای نسخه اول)

| قلم | راهبرد کنترل |
|---|---|
| محاسبه API | مقیاس افقی با حداقل ۲ نمونه؛ autoscale روی CPU/اتصال |
| SFU | نود جدا با پهنای‌باند؛ متریک هزینه/دقیقه تماس؛ سقف هم‌زمانی |
| رسانه | lifecycle + فشرده‌سازی/تبدیل، thumbnail سبک، cache لبه |
| AI | سقف مصرف روزانه کاربر + cache خلاصه‌ها |
| پوش | دسته‌بندی اعلان‌ها و حذف توکن‌های مرده |
