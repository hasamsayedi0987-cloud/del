## چه چیزهایی در گام ۴ اضافه شد؟

| قابلیت | توضیح |
|---|---|
| ساخت گروه | `POST /conversations/group` با `{ title, memberUserIds[] }` — سازنده خودکار **ادمین** می‌شود؛ شناسه‌های تکراری/خودِ سازنده حذف می‌شوند؛ عنوان ۱ تا ۸۰ کاراکتر |
| نقش‌ها | فیلد `role` روی Participant: `admin` / `member` — در DTO اعضا برگردانده می‌شود (`participants[].role`, `myRole`) |
| افزودن عضو | `POST /conversations/:id/members` با `{ userIds[] }` — فقط ادمین؛ **idempotent** (عضو تکراری نادیده گرفته می‌شود) |
| حذف عضو | `DELETE /conversations/:id/members/:userId` — فقط ادمین؛ ادمین نمی‌تواند خودش را با این مسیر حذف کند (`USE_LEAVE`) |
| تغییر نقش | `PATCH /conversations/:id/members/:userId` با `{ role }` — فقط ادمین؛ تغییر نقش خودِ ادمین ممنوع (`CANNOT_CHANGE_OWN_ROLE`) |
| خروج از گروه | `POST /conversations/:id/leave` — **قانون آخرین ادمین**: اگر تنها ادمین باشید و عضو دیگری باشد → 400 `LAST_ADMIN` (اول یکی را ادمین کنید) |
| تغییر نام گروه | `PATCH /conversations/:id` با `{ title }` — فقط ادمین و فقط گروه |
| پیام گروهی | همهٔ مسیرهای گام ۲/۳ (message.send، typing، message.read، unread، since-sync) بدون تغییر روی گروه کار می‌کنند — عضویت یگانه شرط دسترسی است |

## رویدادهای WebSocket تازه

| رویداد | به کجا | payload |
|---|---|---|
| `member.added` | اتاق گروه | `{ conversationId, userId, addedBy }` |
| `conversation.new` | اتاق شخصی هر عضو تازه | `{ conversationId, participantUserIds }` (همان رویداد گام ۲) |
| `member.removed` | اتاق گروه + اتاق شخصی عضو حذف‌شده | `{ conversationId, userId, removedBy, left }` — `left=true` یعنی خودش خارج شد |
| `conversation.updated` | اتاق گروه | هنگام تغییر نام (رفرش لیست) |

**نکتهٔ امنیتی مهم:** هنگام حذف عضو، سرور socketهای او را به‌صورت سمت‌سرور از اتاق گروه خارج می‌کند (`socket.leave`) — کاربر حذف‌شده دیگر هیچ پیام گروهی دریافت نمی‌کند حتی اگر socket باز بماند. هنگام افزودن هم socketهای عضو تازه به اتاق اضافه می‌شوند (بی‌نیاز از join سمت کلاینت).

## خطاهای استاندارد

| کد | وضعیت | معنا |
|---|---|---|
| `NOT_GROUP_ADMIN` | 403 | عمل فقط برای ادمین است |
| `NOT_A_GROUP` | 400 | افزودن عضو فقط برای گروه (نه direct) |
| `USE_LEAVE` | 400 | ادمین نمی‌تواند خودش را حذف کند — خروج بزند |
| `CANNOT_CHANGE_OWN_ROLE` | 400 | تغییر نقش خودِ ادمین ممنوع |
| `LAST_ADMIN` | 400 | آخرین ادمین نمی‌تواند وقتی عضو دیگری هست خارج شود |
| `MEMBER_NOT_FOUND` | 404 | کاربر هدف عضو این گروه نیست |
| `INVALID_TITLE` | 400 | عنوان خالی یا بیش از ۸۰ کاراکتر |

## تغییرات دیتابیس

مهاجرت `group_roles`: ستون `role` (پیش‌فرض `member`) روی جدول `Participant`. هیچ تغییر ساختاری دیگری لازم نبود — `type` و `title` از قبل روی Conversation بودند.

## UI

- **موبایل:** دکمهٔ «+ گروه» در هدر گفتگوها (عنوان + شماره‌های اعضا)؛ ردیف گروه با آواتار مربعی و «N عضو»؛ هدر چت گروه: عنوان + «N عضو · شما ادمین هستید»؛ نام فرستنده روی حباب‌های پیام دیگران؛ «X در حال نوشتن…»؛ تیک خوانده‌شد گروهی (✓✓ وقتی هر عضوی خوانده)؛ اعلان حذف از گروه و بازگشت به لیست
- **دسکتاپ:** دکمهٔ «+ گروه» و مودال ساخت گروه؛ همان نمایش ردیف/هدر/نام فرستنده/تیک گروهی

## رفتار کلاینت هنگام تغییر اعضا

- عضو تازه (حتی آنلاین): رویداد `conversation.new` → رفرش لیست + join اتاق + دریافت پیام‌های بعدی
- عضو حذف‌شده: رویداد `member.removed` روی اتاق شخصی → اعلان + خروج از چت + رفرش لیست (دسترسی REST هم بلافاصله 403 می‌شود)
