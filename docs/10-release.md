# سند ۱۰ — انتشار، سخت‌سازی و پشتیبانی (گام ۱۰)

> **نسخه:** ۱٫۰ · وضعیت گام ۱۰: تست دود ۴۴/۴۴ سبز · رگرسیون کامل گام‌های ۱ تا ۹: **۲۹۳ بررسی سبز** · سنجش بار p95=۹۲ms

## ۱. خلاصهٔ قابلیت‌های گام ۱۰

| قابلیت | شرح | سویچ/متغیر |
|---|---|---|
| پنل مدیریت (دسکتاپ) | متریک‌ها، کاربران + مسدودسازی، صف گزارش‌ها، دفتر اقدامات | نقش `admin` |
| نقش ادمین | ورود شماره‌های فهرست‌شده با نقش admin | `ADMIN_PHONES=+98912…,+98913…` |
| گزارش تخلف | هر کاربر: `POST /users/:id/report` (هرزنامه/آزار/جعل هویت/سایر) | سقف ۲۰/ساعت |
| مسدودسازی کاربر-به-کاربر | DM دوطرفه بسته می‌شود؛ گروه‌ها مستقل‌اند | `POST /users/:id/block` |
| مسدودسازی ادمین | ورود + توکن‌ها + WS همان لحظه بسته می‌شود (گارد زنده) | `POST /admin/users/:id/block` |
| دفتر اقدامات | ثبت همهٔ اقدامات مدیریتی با اقدام‌کننده | جدول `AuditLog` |
| سرآیندهای امنیتی | nosniff / DENY / no-referrer / حذف X-Powered-By / CORS بسته با `DEL_CORS_ORIGINS` | main.ts |
| سقف OTP از هر IP | جدید: `OTP_PER_IP_LIMIT` (پیش‌فرض ۲۰ در ۱۰ دقیقه) | متغیر محیطی |
| سنجش بار | Node probe (p95 کامل ارسال→نمایش) + k6 (p95 HTTP) | `scripts/load/` |
| پشتیبان‌گیری | pg_dump custom + fallback منطقی Node + تمرین بازیابی انجام‌شده | `scripts/backup/` |

## ۲. بوت‌استرپ ادمین

```bash
# در پروداکشن: شماره(های) مدیر را پیش از راه‌اندازی تعیین کنید
ADMIN_PHONES="+989121234567" node apps/api/dist/main.js
# ورود آن شماره با OTP ← نقش admin ← در دسکتاپ دکمهٔ «مدیریت» ظاهر می‌شود
```

## ۴. پشتیبان‌گیری و تمرین بازیابی (الزام فاز ۸)

### ۴.۱ روش پروداکشن

```bash
# شبانه + WAL پیوسته (RPO ≤ ۱۵ دقیقه)
DATABASE_URL="postgresql://…/del" ./scripts/backup/backup.sh /backups/del-$(date +%F).dump
```

- فرمت custom با فشرده‌سازی؛ نگهداری ۳۰ روز؛ یک کپی خارج از سرور (تخریب فاجعه‌بار)
- رسانه‌ها: versioning سطل S3 + همگام‌سازی

### ۴.۲ تمرین انجام‌شده (گام ۱۰ — محیط آزمون)

| مرحله | نتیجه |
|---|---|
| پشتیبان منطقی از del زنده (۱۶ جدول) | ✅ ۷۳ کاربر، ۱۹۲ پیام، ۲۵ گفتگو |
| ساخت پایگاه مقصد + اعمال مهاجرت‌ها | ✅ `del_restore` |
| بازیابی کامل با `scripts/backup/dump-node.js` | ✅ بدون خطای FK |
| مقایسهٔ تعداد رکوردها | ✅ ۷۳ / ۱۹۲ / ۲۵ — یکسان |

**RPO با pg_dump شبانه + WAL پیوسته: ≤ ۱۵ دقیقه** (طبق سند ۰۸). تمرین فصلی تکرار شود و نتیجه در این سند ثبت گردد.

## ۶. تست بار (اهداف سند ۰۱)

```bash
# RTT کامل ارسال→نمایش روی WS (Node)
node scripts/load/probe.js 12 15
# → p50=۴۷ms  p95=۹۲ms  p99=۱۰۳ms  — گم‌شده: ۰  ✅ هدف p95<۳۰۰ms

# بار HTTP API (k6 — p95<۳۰۰ms آستانهٔ سخت)
k6 run -e BASE=http://localhost:3000 -e PAIRS=100 -e RATE=200 scripts/load/k6-messages.js
```

نکتهٔ ظرفیت: اهداف «۱۰هزار WS هم‌زمان و ۵۰۰ تماس هم‌زمان» به استقرار چندنودی (Redis adapter برای WS، کلاستر API و SFU اختصاصی) نیاز دارد؛ در تک‌نود آزمون، ۱۲ جفت فعال با p95=۹۲ms و صفر پیام گم‌شده تأیید شد. اجرای بار کامل روی staging چندنودی پیش از انتشار عمومی الزامی است.
